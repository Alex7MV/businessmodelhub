# 404, Sitemap and Robots — Design

**Date:** 2026-10-08
**Status:** Approved

## Purpose

Three production gaps remain after the mobile navigation work:

1. No `404.html`. A visitor who follows a stale or mistyped link gets whatever
   the server serves by default — an unstyled page with no way back into the
   site.
2. No `sitemap.xml`. Search engines have no authoritative list of pages.
3. No `robots.txt` at the site root.

## Site URL

The site is deployed manually at `https://businessmodelhub.org` on nginx.

The URL lives in one constant:

```python
SITE_URL = "https://businessmodelhub.org"
```

No trailing slash — URLs are composed as `SITE_URL + path`, where `path`
already starts with `/`. Changing the domain means editing one line.

## 404 page

### The output-path trap

`output_path` currently maps `content/<dir>/<stem>.md` to
`<dir>/<stem>/index.html` for every stem except `index`. A content file named
`404.md` would therefore become `dist/404/index.html`.

Hosts serve a custom not-found page from `404.html` **at the site root**. A
page at `dist/404/index.html` would never be used, and the failure would be
silent: the build succeeds, tests pass, and the site keeps serving its default
error page.

So `output_path` gains an explicit case for the `404` stem.

### Content and template

`content/404.md` is an ordinary page rendered by the existing `page.html`. No
new template. `nav_active` is omitted, so no nav item is marked — the visitor is
not on any of the four sections.

The page carries a plain explanation and links to all four sections, so a
visitor arriving on an error can still navigate. Those links are the existing
nav links; the body repeats them as visible prose, since the nav is present but
the point of the page is to be a way out.

## Sitemap

Generated by `build()` from the pages it just wrote. It cannot be hand
maintained: adding an article and forgetting the sitemap is the default
failure, and the failure is invisible.

A helper converts a written output path to its URL:

| Written path | URL |
|---|---|
| `dist/index.html` | `https://businessmodelhub.org/` |
| `dist/articles/index.html` | `https://businessmodelhub.org/articles/` |
| `dist/articles/post/index.html` | `https://businessmodelhub.org/articles/post/` |

Derived from the `index.html` suffix, not from a stored list, so the sitemap
cannot disagree with the output layout.

`404.html` is excluded. A not-found page has no meaningful URL and inviting it
into the index is wrong.

**No `lastmod`.** The repository has no per-file modification history that the
build can read cheaply, and inventing a date would be worse than omitting the
element — search engines treat an incorrect `lastmod` as a signal to
re-crawl and as a quality negative.

## Robots

Generated by `build()`, two lines:

```
User-agent: *
Sitemap: https://businessmodelhub.org/sitemap.xml
```

It is generated rather than placed in `assets/` because asset copying mirrors
the source tree: a file at `assets/robots.txt` would land at
`dist/assets/robots.txt`, while the protocol requires it at the site root. Its
content also depends on `SITE_URL`, so generating keeps one source of truth.

No `Disallow`. The site is intended to be indexed.

## nginx

Nothing to add to the repository. `index index.html;` is in the default nginx
configuration, so the trailing-slash URLs already resolve to the real
`index.html` files.

This cannot be verified from the repository. The single command that confirms
it is:

```
curl -I https://businessmodelhub.org/model-registry/
```

A `200` confirms the layout. A redirect to `.html` means the server config is
non-standard and must be changed on the host, not in this project.

## Files

| File | Change |
|---|---|
| `render.py` | `SITE_URL`, `404` case in `output_path`, `url_for_output`, sitemap and robots emission in `build()`. |
| `content/404.md` | New page. |
| `tests/test_render.py` | Output-path case, sitemap contents, robots contents, 404 links. |

No new templates, no CSS, no JavaScript.

## Testing

- `output_path` maps `404.md` to `<dir>/404.html`, not `<dir>/404/index.html`
- every other stem still maps to a directory `index.html` — the regression that
  the new case must not disturb
- `build()` writes `dist/sitemap.xml`
- the sitemap contains one `<url>` per built page, excluding `404.html`
- every `<loc>` is absolute and starts with `SITE_URL`
- `dist/robots.txt` contains `Sitemap: https://businessmodelhub.org/sitemap.xml`
- the rendered `404.html` contains all four navigation links

## Verification limits

The tests confirm the files are produced and well formed. They cannot confirm
that the host serves `dist/404.html` for an unknown path — that is host
configuration. The `curl -I` above and a request for a deliberately wrong URL
are the real checks, and both must be run after deployment.

## Non-goals

- No `humans.txt`, no `security.txt`.
- No canonical `<link>` tags on pages; not requested and not a stated problem.
- No `sitemap` index file; one flat map is enough at this size.
